This note maps the draft **Bondi_GHZ.pdf**, *Metric reconstruction in a Bondi-like gauge* (17 pages), to the current working-tree code as inspected on 29 September 2026. Section, equation, and figure numbers refer to that PDF. See the [repository overview](../README.md) for the implemented pipeline and build instructions. The local LaTeX draft has since changed, so its numbering should not be substituted automatically. This is a source-code map, not a fresh numerical validation; notebooks and numerical tests were inspected but not rerun.

The main division is: **The implemented Kerr m-mode completion is in `tools/bondi_kerr_m_mode_check.cpp`, driven by Julia input; `asymptotic/` supplies the Weyl-input seed solver and Schwarzschild references; `transport/` implements the GHZ corrector.** The `geom/`, `ghp/`, and `spectral/` modules supply the common machinery. Puncture generation and much of the sourced reconstruction remain in Mathematica notebooks. Julia supplies an alternative asymptotic input for the Kerr diagnostic. Several important operations are free functions or notebook definitions, rather than C++ classes.

The implemented data flow is:

1. **Julia amplitudes → angular input.** The exporter computes separated spin −2 Teukolsky modes for ±m, expands their spheroidal harmonics into spherical coefficients, and sums the input multipoles. It exports `q = -sum(Zinf * S)` in the rho-coefficient convention. C++ evaluates those coefficients as reduced angular fields on the LGL nodes.
2. **Angular input → HMS pair.** With `A = Held-edth-prime^4` and `B = Held-edth^4`, the grid solve uses `A f + 3 i M omega fbar = (2 i / omega) q` and `B fbar + 3 i M omega f = (2 i / omega) qbar`. The executable fixes M=1. `qbar` comes from the conjugate of the reflected (−m,−omega) field, not conjugation at fixed mode.
3. **HMS pair → Kerr Hertz completion and gauge.** `potential` constructs the four Hertz coefficients and their radial polynomial. In a separate branch, `lie` constructs the gauge contribution from the same seeds. Both use the nonzero-a reduced Held operators.
4. **Completion → reconstructed metric → adjusted metric.** `primitive/rec` applies the metric reconstruction, and the radius loop adds `rec + lie` in the code convention. The CSV stores norms and complex equatorial samples; the plot checks the surviving inverse-radius behavior.

The windowed effective source feeds a **separate corrector branch**, `T^E_ab → source conditioning → solve_worldtube_hierarchy → x_ab`. It does not consume the Julia infinity-amplitude CSV. The executable's current driver is a circular equatorial m=±2 example at r0=10 with adjustable a and source multipole cutoff; its implemented Kerr completion should not be confused with a complete generic-orbit residual-metric assembly.

The paper's direct leading-Weyl-coefficient route remains in [BondiHeldSeedSolve.hpp](../include/ghz/asymptotic/BondiHeldSeedSolve.hpp): `BondiHeldSeedSolver::apply/solve` implements the eighth-order angular inversion. [SchwarzschildPsi0Modes.hpp](../include/ghz/asymptotic/SchwarzschildPsi0Modes.hpp) imports fitted Schwarzschild coefficients and supplies the analytic seed reference. [SchwarzschildBondiMetric.hpp](../include/ghz/asymptotic/SchwarzschildBondiMetric.hpp), [BondiHeldMetricGrid.hpp](../include/ghz/asymptotic/BondiHeldMetricGrid.hpp), and [SchwarzschildBondiGauge.hpp](../include/ghz/asymptotic/SchwarzschildBondiGauge.hpp) supply the Schwarzschild modal/grid completion and gauge references. These complement the implemented Kerr path above.

**Sections III, IV, and V E: from asymptotic Weyl data to the Bondi completion.** For the Julia-driven Kerr m-mode implementation, start with the pipeline above. For the paper's direct Weyl-input route and Schwarzschild validation, the reading order is:

1. [SchwarzschildPsi0Modes.cpp](../src/ghz/asymptotic/SchwarzschildPsi0Modes.cpp) reads the fitted $(\ell,m)$ coefficients and supplies harmonics, pole factors, and the analytic seed. `exact_reduced_seed` implements the Schwarzschild algebraic inversion corresponding to Eq. (19), then sums over $\ell$. `summed_reduced_mode` supplies the angular-grid input.
2. [BondiHeldSeedSolve.cpp](../src/ghz/asymptotic/BondiHeldSeedSolve.cpp) implements the conjugate, spin-$+2$ version of Eq. (14). `apply` lowers four times, raises four times, and adds $9M^2\omega^2 f$. `solve` constructs the dense matrix column by column and uses row/column equilibration, full-pivot LU, and iterative refinement. This directly matches the numerical description in Sec. V E, pp. 9–10. The angular operators can include Kerr spin; this does not make the separate Schwarzschild metric formulas generic Kerr formulas.
3. [SchwarzschildBondiMetric.hpp](../include/ghz/asymptotic/SchwarzschildBondiMetric.hpp) defines `RadialLaurent`, `MetricComponentParts`, and `SchwarzschildBondiMetricMode`. The modal `mode` and `summed_at_z` methods construct the `nn`, `nm`, and `mm` components. Each stores reconstructed, gauge, and adjusted pieces separately, with coefficients ordered as $r,1,r^{-1},r^{-2}$.
4. [BondiHeldMetricGrid.hpp](../include/ghz/asymptotic/BondiHeldMetricGrid.hpp) defines the analogous grid objects: `MetricGridLaurent`, `MetricGridParts`, and `BondiHeldMetricGrid`. `BondiHeldMetricReconstruction::reconstruct` performs the Schwarzschild construction using Held derivatives on the angular grid, without an $\ell$ projection. This is the direct representation of Eq. (35) and its pointwise cancellation test.
5. [SchwarzschildBondiGauge.cpp](../src/ghz/asymptotic/SchwarzschildBondiGauge.cpp) provides `held_mode`, `summed_reduced_held_mode`, and `np_mode_at_radius`, corresponding to the gauge-vector construction. The companion metric routines evaluate its Lie contribution.

Equation (33)'s pole factor is represented both by `SchwarzschildPsi0Modes::pole_factor`/the reduced harmonic methods and by the reduced Held operators. A field named `reduced_seed` is the pole-factorized HMS, not an ordinary scalar amplitude at the poles. Likewise, the `phi[0]` through `phi[3]` arrays internal to reconstruction represent Hertz completion coefficients, not the seed itself.

The notebook counterparts are [BondiGauge_Adjusted.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/BondiGauge_Adjusted.nb) for the Schwarzschild adjustment, [BondiGauge_Adjusted_Generic.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/BondiGauge_Adjusted_Generic.nb) for the generic angular construction, and [BondiGauge_Adjusted_redshift.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/BondiGauge_Adjusted_redshift.nb) for gauge/redshift checks.

**Section V D and Appendix B: Teukolsky source, Weyl solution, and radial Hertz inversion.** [TeukolskySource.hpp](../include/ghz/source/TeukolskySource.hpp) and [TeukolskySource.cpp](../src/ghz/source/TeukolskySource.cpp) contain `TeukolskySourceComponents`, `TeukolskySourceCoefficients`, `TeukolskySourceOperators`, and `apply_s0_teukolsky_source`. They assemble the spin-$+2$ source from `Tll`, `Tlm_sym`, and `Tmm`. This is the source side of Eq. (10)/Appendix B, expressed using NP/GHP operators; its normalization should be checked before identifying it literally with the draft's expanded $T_0$.

The corresponding Mathematica path includes [Teuk_hS1_lm_Projection_mixedCMBLcoords.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/Teuk_hS1_lm_Projection_mixedCMBLcoords.nb), [Plus2ProjectionCachedParallel.wl](../MathematicaNotebooks/EffectiveSource/lm_mode/Plus2ProjectionCachedParallel.wl), and [psi0S_hS1_lm_Projection_mixedCMBLcoords.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/psi0S_hS1_lm_Projection_mixedCMBLcoords.nb). I did **not** locate a C++ implementation of the complete two-dimensional retarded Teukolsky PDE solve described around Eqs. (31)–(32), or a general C++ fourfold radial inversion for $\Phi^{\min}$. The C++ Bondi tests start from already fitted asymptotic data, imported through [export_schwarzschild_psi0_wxf.py](../scripts/export_schwarzschild_psi0_wxf.py) into [psi0_schwarzschild_r0_10_lmax20_mostly_minus.csv](../tests/data/psi0_schwarzschild_r0_10_lmax20_mostly_minus.csv). Thus a source-assembly class should not be read as evidence that the full Weyl PDE solver is present.

**Kerr completion and Appendix A.** The most concrete generic-Kerr C++ implementation is currently [bondi_kerr_m_mode_check.cpp](../tools/bondi_kerr_m_mode_check.cpp), rather than a library class under `asymptotic/`. Its local `KerrDiagnostic` class has:

- `potential`: the triangular Hertz completion and polynomial in $\rho^{-1}$, corresponding to Eqs. (13), (15).
- `primitive` and `rec`: reconstruction of the `nn`, `nm`, and `mm` components from the completion.
- `lie`: residual gauge construction and Lie components, the computational counterpart of Eq. (16) and Appendix A. It uses the radial gauge-vector form from the cited Hollands–Toomani construction rather than copying the draft's expanded Appendix A expressions term by term.
- `ReducedField` and `RadialJet`: local containers retaining pole factors/weights and radial derivatives through second order.

This diagnostic obtains its seed by a **coupled fourth-order system driven by $\psi_4$**. That is an alternative input route, not the literal $\psi^{5\circ}$-driven eighth-order solve described in the PDF. [export_gsn_circular_m_mode.jl](../scripts/export_gsn_circular_m_mode.jl) obtains spin-$-2$ infinity amplitudes and exports their spherical expansion for the fixed $m=\pm2$ circular-orbit test. Its producer is `Teukolsky_pointparticle_mode` in [GeneralizedSasakiNakamura.jl](https://github.com/ricokaloklo/GeneralizedSasakiNakamura.jl). The diagnostic sums the angular input before solving on the LGL grid. [GSN_Bondi_interface.md](GSN_Bondi_interface.md) and [GSN_Kerr_m_mode_decay.md](GSN_Kerr_m_mode_decay.md) document this route and its conventions.

**Section V G: the banded Kerr $(\ell,m)$ construction.** [BondiEllMBanded.hpp](../include/ghz/asymptotic/BondiEllMBanded.hpp) is a direct but partial counterpart of Eqs. (40)–(43): `cos_theta_lower_coefficient`, `cos_theta_diagonal_coefficient`, and `cos_theta_matrix` implement the tridiagonal cosine coupling, while `phi_adjustment_horner` evaluates the completion with $R=-rI+iaC$. It takes the four completion coefficient vectors as inputs; it does not construct the entire banded reconstruction pipeline. Additional matrix-action checks for Held derivatives, $\Omega^\circ$, and $\tau^\circ$ live in `bondi_kerr_m_mode_check.cpp`. The broader notebook implementation is `BondiGauge_Adjusted_Generic.nb`, particularly `CosThetaMatrix`, `fHS`, and `PhiAdjustmentYVector`. The helper's three extra multipoles concern multiplication by $\rho^{-3}$; they do not replace the larger buffer required by the preceding Held chains discussed in the paper.

**Appendix C: generic bound orbits.** [KerrOrbit.hpp](../include/ghz/orbit/KerrOrbit.hpp) and [KerrOrbit.cpp](../src/ghz/orbit/KerrOrbit.cpp), principally `KerrBoundOrbit`, implement the orbit, Mino/coordinate-time frequencies, phases, and Fourier ingredients corresponding to Eqs. (C2)–(C5). `KerrCircularEquatorialOrbit` is the circular specialization used by the Bondi gauge checks. [SourceTorusFrequencies.hpp](../include/ghz/orbit/SourceTorusFrequencies.hpp) carries the source frequencies, and `SpectralFieldVectorized::Modes` stores `{m,kr,kz}`. These support the generic-orbit extension, but are not a complete implementation of the phase-dependent puncture plus torus transform in Eqs. (C6)–(C14). No complete implementation of that source pipeline was identified in this inspection.

**Conventions and limits to keep alongside the map.** The PDF writes a minus gauge term in Eqs. (1), (22); the current C++ metric classes explicitly assemble `reconstructed + lie_zeta`, following their notebook convention. `KerrDiagnostic::potential` also explicitly uses half the paper's Hertz potential with its corresponding reconstruction normalization. Consequently these are structural correspondences, not a claim that every displayed draft formula can be copied into the code unchanged. The WXF exporter separately changes mostly-plus input to mostly-minus output; the Julia path separately converts an inverse-radius coefficient to a coefficient in powers of $\rho$. Those sign changes serve different purposes.

The C++ metric routines reviewed here compute the **asymptotic completion and its gauge adjustment**. They do not include the minimal Hertz solution, sourced corrector, and Kerr zero mode in a single result. The grid metric routine explicitly requires nonzero frequency, and the modal falloff tests skip $m=0$; the static/nonradiative sector needs separate treatment. The Kerr falloff diagnostic is a fixed circular-orbit, single-$m$ test, not a full generic-orbit or all-mode residual metric. Finally, its surviving $1/r$ coefficients support the paper's discussion of asymptotic observables, but dedicated normalized Bondi-news, mass-aspect, and angular-momentum-aspect APIs were not identified.

For a first pass through the m-mode scheme, read `export_gsn_circular_m_mode.jl`, then the angular solve and `KerrDiagnostic` methods in `bondi_kerr_m_mode_check.cpp`, followed by the separate corrector hierarchy. Use the seed solver and Schwarzschild metric implementations as the direct-Weyl-input route and validation references. The notebooks are the next stop for the puncture, sourced radial reconstruction, and full observable calculations.
