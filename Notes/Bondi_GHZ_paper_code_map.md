This map connects *Metric reconstruction in a Bondi-like gauge* to the files, classes, and functions used in its numerical construction. Section, equation, and figure numbers refer to the this paper. See the [repository overview](../README.md) for the pipeline and build instructions.

The main division is: **The implemented Kerr m-mode completion is in `tools/bondi_kerr_m_mode_check.cpp`, driven by Julia input; `asymptotic/` supplies the Weyl-input seed solver and Schwarzschild references; `transport/` implements the GHZ corrector.** The `geom/`, `ghp/`, and `spectral/` modules supply the common machinery. The implemented data flow is:

1. **Julia amplitudes → angular input.** The exporter computes separated spin −2 Teukolsky modes for ±m, expands their spheroidal harmonics into spherical coefficients, and sums the input multipoles. It exports `q = -sum(Zinf * S)` in the rho-coefficient convention. C++ evaluates those coefficients as reduced angular fields on the LGL nodes.
2. **Angular input → HMS pair.** With `A = Held-edth-prime^4` and `B = Held-edth^4`, the grid solve uses `A f + 3 i M omega fbar = (2 i / omega) q` and `B fbar + 3 i M omega f = (2 i / omega) qbar`. The executable fixes M=1. `qbar` comes from the conjugate of the reflected (−m,−omega) field, not conjugation at fixed mode.
3. **HMS pair → Kerr Hertz completion and gauge.** `potential` constructs the four Hertz coefficients and their radial polynomial. In a separate branch, `lie` constructs the gauge contribution from the same seeds. Both use the nonzero-a reduced Held operators.
4. **Completion → reconstructed metric → adjusted metric.** `primitive/rec` applies the metric reconstruction, and the radius loop adds `rec + lie` in the code convention. The CSV stores norms and complex equatorial samples; the plot checks the surviving inverse-radius behavior.

The windowed effective source feeds a **separate corrector branch**, `T^E_ab → source conditioning → solve_worldtube_hierarchy → x_ab`. The executable's current driver is a circular equatorial m=±2 example at r0=10 with adjustable a and source multipole cutoff; the completion is evaluated directly on the angular grid.

The paper's direct leading-Weyl-coefficient route remains in [BondiHeldSeedSolve.hpp](../include/ghz/asymptotic/BondiHeldSeedSolve.hpp): `BondiHeldSeedSolver::apply/solve` implements the eighth-order angular inversion. [SchwarzschildPsi0Modes.hpp](../include/ghz/asymptotic/SchwarzschildPsi0Modes.hpp) imports fitted Schwarzschild coefficients and supplies the analytic seed reference. [SchwarzschildBondiMetric.hpp](../include/ghz/asymptotic/SchwarzschildBondiMetric.hpp), [BondiHeldMetricGrid.hpp](../include/ghz/asymptotic/BondiHeldMetricGrid.hpp), and [SchwarzschildBondiGauge.hpp](../include/ghz/asymptotic/SchwarzschildBondiGauge.hpp) supply the Schwarzschild modal/grid completion and gauge references. These complement the implemented Kerr path above.

**Sections III, IV, and V E: from asymptotic Weyl data to the Bondi completion.** For the Julia-driven Kerr m-mode implementation, start with the pipeline above. For the paper's direct Weyl-input route and Schwarzschild validation, the reading order is:

1. [SchwarzschildPsi0Modes.cpp](../src/ghz/asymptotic/SchwarzschildPsi0Modes.cpp) reads the fitted $(\ell,m)$ coefficients and supplies harmonics, pole factors, and the analytic seed. `exact_reduced_seed` implements the Schwarzschild algebraic inversion corresponding to Eq. (19), then sums over $\ell$. `summed_reduced_mode` supplies the angular-grid input.
2. [BondiHeldSeedSolve.cpp](../src/ghz/asymptotic/BondiHeldSeedSolve.cpp) implements the conjugate, spin-$+2$ version of Eq. (14). `apply` lowers four times, raises four times, and adds $9M^2\omega^2 f$. `solve` constructs the dense matrix column by column and uses row/column equilibration, full-pivot LU, and iterative refinement. This directly matches the numerical description in Sec. V E, pp. 9–10. The angular operators include the Kerr-spin dependence.
3. [SchwarzschildBondiMetric.hpp](../include/ghz/asymptotic/SchwarzschildBondiMetric.hpp) defines `RadialLaurent`, `MetricComponentParts`, and `SchwarzschildBondiMetricMode`. The modal `mode` and `summed_at_z` methods construct the `nn`, `nm`, and `mm` components. Each stores reconstructed, gauge, and adjusted pieces separately, with coefficients ordered as $r,1,r^{-1},r^{-2}$.
4. [BondiHeldMetricGrid.hpp](../include/ghz/asymptotic/BondiHeldMetricGrid.hpp) defines the analogous grid objects: `MetricGridLaurent`, `MetricGridParts`, and `BondiHeldMetricGrid`. `BondiHeldMetricReconstruction::reconstruct` performs the Schwarzschild construction using Held derivatives on the angular grid, without an $\ell$ projection. This is the direct representation of Eq. (35) and its pointwise cancellation test.
5. [SchwarzschildBondiGauge.cpp](../src/ghz/asymptotic/SchwarzschildBondiGauge.cpp) provides `held_mode`, `summed_reduced_held_mode`, and `np_mode_at_radius`, corresponding to the gauge-vector construction. The companion metric routines evaluate its Lie contribution.

Equation (33)'s pole factor is represented both by `SchwarzschildPsi0Modes::pole_factor`/the reduced harmonic methods and by the reduced Held operators. The field `reduced_seed` stores the pole-factorized HMS; the internal arrays `phi[0]` through `phi[3]` store the Hertz completion coefficients.

The notebook counterparts are [BondiGauge_Adjusted.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/BondiGauge_Adjusted.nb) for the Schwarzschild adjustment, [BondiGauge_Adjusted_Generic.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/BondiGauge_Adjusted_Generic.nb) for the generic angular construction, and [BondiGauge_Adjusted_redshift.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/BondiGauge_Adjusted_redshift.nb) for gauge/redshift checks.

**Section V D and Appendix B: Teukolsky source, Weyl solution, and radial Hertz inversion.** [TeukolskySource.hpp](../include/ghz/source/TeukolskySource.hpp) and [TeukolskySource.cpp](../src/ghz/source/TeukolskySource.cpp) contain `TeukolskySourceComponents`, `TeukolskySourceCoefficients`, `TeukolskySourceOperators`, and `apply_s0_teukolsky_source`. They assemble the spin-$+2$ source from `Tll`, `Tlm_sym`, and `Tmm`. This implements the source side of Eq. (10)/Appendix B using NP/GHP operators.

The corresponding Mathematica path includes [Teuk_hS1_lm_Projection_mixedCMBLcoords.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/Teuk_hS1_lm_Projection_mixedCMBLcoords.nb), [Plus2ProjectionCachedParallel.wl](../MathematicaNotebooks/EffectiveSource/lm_mode/Plus2ProjectionCachedParallel.wl), and [psi0S_hS1_lm_Projection_mixedCMBLcoords.nb](../MathematicaNotebooks/EffectiveSource/lm_mode/psi0S_hS1_lm_Projection_mixedCMBLcoords.nb). These cover source/puncture projection and cached radial data. [AngularProjection.hpp](../include/ghz/source/AngularProjection.hpp) supplies C++ projection utilities. The large inward reconstruction notebook imports the BHPT `Teukolsky` package and contains the radial reconstruction workflow.

**Kerr completion and Appendix A.** The most concrete generic-Kerr C++ implementation is currently [bondi_kerr_m_mode_check.cpp](../tools/bondi_kerr_m_mode_check.cpp), which contains the angular solve and radial evaluation. Its local `KerrDiagnostic` class has:

- `potential`: the triangular Hertz completion and polynomial in $\rho^{-1}$, corresponding to Eqs. (13), (15).
- `primitive` and `rec`: reconstruction of the `nn`, `nm`, and `mm` components from the completion.
- `lie`: residual gauge construction and Lie components, the computational counterpart of Eq. (16) and Appendix A. It uses the radial gauge-vector form from the cited Hollands–Toomani construction rather than copying the draft's expanded Appendix A expressions term by term.
- `ReducedField` and `RadialJet`: local containers retaining pole factors/weights and radial derivatives through second order.

This diagnostic obtains its seed by a **coupled fourth-order system driven by $\psi_4$**. This supplies the HMS through an alternative to the paper's $\psi^{5\circ}$-driven eighth-order equation. [export_gsn_circular_m_mode.jl](../scripts/export_gsn_circular_m_mode.jl) obtains spin-$-2$ infinity amplitudes and exports their spherical expansion for the fixed $m=\pm2$ circular-orbit test. Its producer is `Teukolsky_pointparticle_mode` in [GeneralizedSasakiNakamura.jl](https://github.com/ricokaloklo/GeneralizedSasakiNakamura.jl). The diagnostic sums the angular input before solving on the LGL grid. [GSN_Bondi_interface.md](GSN_Bondi_interface.md) and [GSN_Kerr_m_mode_decay.md](GSN_Kerr_m_mode_decay.md) document this route and its conventions.

**Section V G: the banded Kerr $(\ell,m)$ construction.** [BondiEllMBanded.hpp](../include/ghz/asymptotic/BondiEllMBanded.hpp) implements the coefficient-space operations in Eqs. (40)–(43): `cos_theta_lower_coefficient`, `cos_theta_diagonal_coefficient`, and `cos_theta_matrix` implement the tridiagonal cosine coupling, while `phi_adjustment_horner` evaluates the completion with $R=-rI+iaC$. It takes the four completion coefficient vectors as inputs. Additional matrix-action checks for Held derivatives, $\Omega^\circ$, and $\tau^\circ$ live in `bondi_kerr_m_mode_check.cpp`. The broader notebook implementation is `BondiGauge_Adjusted_Generic.nb`, particularly `CosThetaMatrix`, `fHS`, and `PhiAdjustmentYVector`. The helper uses three extra multipoles for multiplication by $\rho^{-3}$, alongside the buffer needed for the preceding Held chains.

**Appendix C: generic bound orbits.** [KerrOrbit.hpp](../include/ghz/orbit/KerrOrbit.hpp) and [KerrOrbit.cpp](../src/ghz/orbit/KerrOrbit.cpp), principally `KerrBoundOrbit`, implement the orbit, Mino/coordinate-time frequencies, phases, and Fourier ingredients corresponding to Eqs. These provide the orbital ingredients and mode labels for the generic-orbit construction discussed in Appendix C.

For a first pass through the m-mode scheme, read `export_gsn_circular_m_mode.jl`, then the angular solve and `KerrDiagnostic` methods in `bondi_kerr_m_mode_check.cpp`, followed by the separate corrector hierarchy. Use the seed solver and Schwarzschild metric implementations as the direct-Weyl-input route and validation references. The notebooks are the next stop for the puncture, sourced radial reconstruction, and full observable calculations.
